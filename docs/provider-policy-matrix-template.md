## Engineering gate

- `unreviewed` or `unclear` disables the relevant feature by default.
- `prohibited` must be enforced by code-level feature gates, not only UI warnings.
- Review must be repeated when terms change or a new integration is introduced.
- Store the review version/date and the exact feature flags enabled.


## Application attestation semantics

Mosaic's `allowed_with_conditions` status is a **user-recorded attestation**, not a legal conclusion generated by Mosaic. The user must supply an HTTPS policy reference, a policy version or review date, notes describing the reviewed operations/conditions, and an explicit acknowledgement. External cross-provider handoffs require both source and destination providers to have this status, plus the source's explicit cross-provider-transfer permission. `restricted`, `prohibited`, and `unreviewed` block those handoffs. Review records should be revisited when provider terms change.
